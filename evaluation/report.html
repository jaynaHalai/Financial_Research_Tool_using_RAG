Measurement

The first result was a measurement artifact

An earlier version of this evaluation scored retrieval with two different coverage functions in two different scripts, then compared the outputs to each other. One awarded full credit only on a verbatim match; the other awarded partial credit for each gold word appearing anywhere in the retrieved text.

The second rule is far more generous than it looks. Financial prose reuses the same vocabulary constantly, so when the retrieval misses completely, words like revenue, total and 2025 still turn up in whatever was returned:

What this invalidated

The original report claimed reranking lifted recall from 0.502 to 0.994. The pre-rerank figure came from the strict function and the post-rerank figure from the generous one, so the gain was mostly a change of ruler. Under one rule, naive reranking actually hurt.

Everything below uses strict verbatim containment, on the answerable questions only. It is a harsh metric — a chunk that contains the answer but splits the gold span across a boundary scores zero — but it is the same harsh metric everywhere, so the comparisons hold.

Chunking

Semantic chunks beat fixed windows

Two strategies over the same cleaned text: fixed 500-word windows with 50 words of overlap, and embedding-similarity breakpoints grouped toward a 500-word target. Compared here on dense retrieval with no reranking, so only the chunking differs.

The semantic chunker's size guard does not hold

Worth stating plainly, because it shapes the reranking result that follows. The max-size guard only splits between semantic units, so any single unit longer than the 600-word ceiling passes through whole:

Retrieval

Hybrid pays off at depth, not at the top

Dense search over FAISS, BM25 over the same chunks, and the two fused by reciprocal rank fusion. BM25 tokenisation preserves figures like 4,007 and 87.1% as single tokens, which is the whole reason to have it for a financial filing.

On its own, hybrid looks like a downgrade: it trades top-3 precision for recall at depth. That trade is only worth making if something downstream can reorder the deeper pool — which is exactly what a working reranker does.

Reranking

A cross-encoder that reads 18% of a chunk

The reranker is ms-marco-MiniLM-L-6-v2, which truncates its input at 512 tokens. The largest semantic chunk is 2,798 tokens of dense financial text. Passing whole chunks to it means scoring each candidate on roughly its first fifth, and silently discarding the rest.

For the chunk holding Arm's consolidated income statement, the gold span sits 5% of the way in — it happens to survive. For others it does not, and the reranker confidently demotes a chunk whose evidence it never read. The fix is to score overlapping 250-word windows and give each chunk the score of its best window.

This is the result the project turns on. A reranking step that is wired in correctly but fed the wrong input shape looks like evidence that reranking does not help, when it is really evidence that the model never saw the text it was asked to judge.

Why citation validity is tracked separately

Printed page numbers survive inside the chunk text as bare digits. During testing the model answered correctly but cited page 125 — a number it had copied out of the body text, not from any page label it was shown. The content was right and a faithfulness judge passes it, because the judge checks claims against evidence, not citations against offered sources.

Citation validity closes that gap: every page an answer cites must fall within a page range actually offered as evidence. It sits at 100% after relabelling each evidence block with its page reference, but the failure mode is real and worth keeping instrumented.

Caveats

What these numbers do not establish

  • Ten answerable questions is a small benchmark. One question is worth 0.10, so a gap of that size is a single item, not a trend.
  • The corpus is one document. Nothing here tests retrieval across filings, across companies, or across reporting periods.
  • Faithfulness is judged by a model, not a human. It checks grounding against retrieved evidence, and will not catch an answer that is faithful to evidence which is itself the wrong passage.
  • The strict metric penalises correct retrievals whose gold span is split across a chunk boundary. It understates real-world usefulness and is chosen for comparability, not realism.
  • Page numbers are recovered heuristically, from the ascending subsequence of standalone numbers in the cleaned text. Validated against every gold span, but not against all 201 pages.
  • Latency is measured warm, single-user, with no concurrency. Cold start adds several seconds while the cross-encoder loads.
